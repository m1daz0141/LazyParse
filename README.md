# LazyParse

PSO2 Classic x64用の取得・集計・コンパクトGUI。旧OverParseの配置を踏襲したPython/Tk製の新しいGUIです。NGSは対象外です。

## 主な機能

- 人物・攻撃別の与ダメージ、被ダメージ、DPS、JA、Crit、最大ヒット。
- ペットの所有者への帰属。負数の回復候補をダメージ集計から除外。
- 発生元IDが0のバーンは集計から除外。発生元を識別できるバーンは通常どおり集計し、除外した原本と理由も保持。
- 連続時間の「クエスト中」と従来の区間合算「ダメージ計測」を切替。
- クエストごとの自動計測・クリア通知での時計固定・履歴のJSON保存（試験中）。残滓・最終決戦は成功クリアと失敗後帰還を分け、クリア後の帰還では終了時刻を維持します。
- 手動編集できる攻撃名CSV、Timeの小数表示切替。

## 必要環境

単体exe版はWindows x64で動作し、Python・PowerShellの別途インストールは不要です。`dist/LazyParse.exe`を任意の書き込み可能なフォルダーへ置いて起動します。初回にPSO2の`pso2_bin/sub`を選択すると、ゲームの版と既存ファイルを確認して追加ローダー`eos_gaming.dll`を配置し、パスを記憶します。以後の起動でフォルダーやDLLが見つからない場合はエラーを表示して再選択します。「設定」から再配置・撤去もできます。ゲーム起動中は配置変更を行いません。

exeの隣に`config/`と小文字の`logs/`を自動生成します。`config/`に設定・編集用CSV・展開した取得DLL、`logs/`にTXT、`logs/history/`に集計JSON、`logs/captures/`に元の取得記録を保存します。exeとこれらのフォルダーを一緒に移動すれば設定や履歴を引き継げます。移動後はゲームを終了した状態で「設定」から配置を更新してください。既存の設定・CSVは起動時に上書きしません。

更新は`LazyParse.exe`の差し替えで行えます。新しいexeを最初に起動するとDLL配置先の選択画面を再表示します。Windowsのファイル情報にはバージョンを記載し、更新検知にはexe本体のSHA-256も使うため、GUIだけの変更でも検知します。配置に成功するまで更新確認は保存せず、キャンセル時は次回も再表示します。初めてこの機能へ移行する場合も1回再選択が必要です。

起動時・GUI起動中の5秒ごとの確認・記録開始直前に、`pso2bridge.dll`と`pso2classic.dll`を確認します。未対応のハッシュなら対象ファイルと対応／検出SHA-256をエラー表示し、配置と新しい記録開始を中止します。定期確認ではファイル属性が変わった場合に再ハッシュし、記録開始直前は毎回ハッシュを照合します。停止・取得終了と保存済みログの閲覧は引き続き利用できます。

ソース版にはPython 3.13とTkを使用します。

```powershell
./Start-LazyParse.ps1
```

GUIからゲームを起動することはありません。取得部は対応版のSHA-256を照合し、未対応版では動作を保留します。[取得部のビルド・配置](tools/native_capture/README.md)も参照してください。ソース版の初回起動では、従来のCSV・GUI設定・履歴を新しい保存先へコピーし、元ファイルを保持します。ルートの`quests.csv`などは初期値用で、以後GUIが使う編集対象は`config/`内のCSVです。

### 単体exeをビルドする

単体exeのビルドにはPython、PowerShell 7、固定版のZigを使用します。MinHookを使う旧方式は調査用で、単体exeには含めません。依存のダウンロードは明示したビルド操作時だけです。

```powershell
./tools/native_capture/build.ps1 -Bootstrap # ツールチェーンを初めて用意する場合
./Build-LazyParse.ps1 -InstallBuildTools
```

成果物は`dist/LazyParse.exe`です。[PyInstallerのone-file形式](https://pyinstaller.org/en/stable/operating-mode.html)でPython/Tkと取得部を同梱し、実行時の一時展開とは別に、ゲームが参照するDLLを`config/native/`へ保持します。ビルド済みDLLに開発機の保存パスを固定していません。公開前には対応ゲーム版での実機試験が必要です。

保存済みデータを開く場合:

```powershell
./Start-LazyParse.ps1 -Capture ./my-recording/capture.opcap
```

## 操作と設定

上部メニューは「計測 / DPS / 解析 / 設定 / 表示 / ログ」。計測から記録開始・停止・保存して次の計測・取得終了を操作します。GUIを閉じるだけでは取得を停止しません。行のダブルクリックで攻撃別・発生元・識別品質を確認できます。

- **DPS→クエスト中**: 最初の与ダメージから終了まで。無攻撃・移動時間を含む連続時間（既定）。
- **DPS→ダメージ計測**: 既定10秒以上の無ダメージで分けた正値区間の最初～最後を合算する従来方式。合計0秒のDPSは「—」。
- **計測→Timeを小数点まで表示**: ONで小数2桁、OFFで整数秒切り捨て。DPSの計算精度は変えません。
- **計測→クエストごとに自動計測（試験中）**: 記録を続けながら周回を区分し、クリア候補で時計を固定。帰還結果は後から紐付け、次の受注で新計測へ切り替えます。未確定・終了後データは別枠に保持します。
- **解析→攻撃名CSVを開く／再読込**: `config/skills.csv`をUTF-8で編集します。形式は「名前,10進ID,種別または注記,説明,…」。固定辞書より優先して同一IDを上書き・新IDを追加。不正時は固定辞書へ戻し診断へ理由を表示します。人物・所有者・回復・JA/Critの分類は変えません。
- **解析→クエスト名CSVを開く／再読込**: `config/quests.csv`をUTF-8で編集します。列は`quest_id,name,note`。一覧で名前を照合した810件（ID0のザウーダン討伐を含む）と、実測したディバイドのステージID1005の表示名を登録しています。未登録IDは「不明クエスト（ID: …）」と表示します。ID0の計測時の対応は未照合です。名前の変更は計測の区切りに影響しません。難易度・深度はIDだけから推測しません。
- **現在の一覧／履歴の項目を右クリック→計測結果をTXTへ保存**: 旧OverParseに近い形式で、全プレイヤーのDamage・Taken・DPS・JA・Crit・最大ヒットと、攻撃別の割合・ヒット数・最小／平均／最大値を出力します。「自分のみ表示」等の絞り込みに関係なく全プレイヤーが対象で、人物名の匿名表示設定は反映します。
- **計測→計測終了時にTXTを自動出力**: 既定OFF。GUI起動中、有効化後に監視した計測を、クエストの終了／切替または手動計測の停止時に`logs/`へ出力します。既存の過去履歴は一括出力しません。後着データは自動生成ファイルへ反映し、手で編集されたファイルは別名で保持します。`.auto-text-index.json`は自動出力したファイル名・内容ハッシュ・出力設定を記録し、後着更新と手編集の保護に使うローカル索引です。

TXTのファイル名は`LazyParse_(クエスト名)_yyyy-MM-dd_HH-mm-ss.txt`、手動計測は`LazyParse_Manual_yyyy-MM-dd_HH-mm-ss.txt`。日時は最初の与ダメージ（なければ最初の記録）の日本時間で、日時情報のない古い集計JSONでは出力時刻を使います。同名は連番で回避します。DPS方式・Timeの小数表示は出力時の設定を使い、自動出力済みのファイルは後着データの反映時も当初の設定を維持します。古いJSONだけでは最小値などを復元できない場合があり、「—」と表示します。元OPCAPを開けば再集計できます。「ログ→TXT出力フォルダーを開く」で保存先を開けます。

設定は`config/preferences.json`、自動保存は`logs/history/`。ゲームフォルダーは配置成功時、その他の画面設定は通常終了時に保存します。JA除外は`config/ja_exclusions.csv`（`attack_id,reason`のCSV、または1行1 ID）。既存のローカル除外設定があれば初回移行時に保持します。ペットはJA対象外です。

編集用CSVはUTF-8で保存してください。BOM付き・BOMなしの両方に対応します。Shift_JIS（ANSI）やUTF-16は現在の読み込み対象ではありません。

クリア判定は、確認済みの完了通知の種類・サイズ・順序が一致すれば、クエストIDや名前の登録有無にかかわらず適用します。通知の連番が隣接し、先頭から50ms以内に一式が揃うことを確認します。未確認の通知形式は追加の照合が必要です。ディバイドはステージごとの再計測を維持し、ステップ21〜25で観測した最終ステージID1005の名前は「決戦：最終標的」です。他の最終ステージの実機確認やディバイド失敗時の照合は残っています。クリア済みの計測は帰還・リザルト通知で再停止せず、結果だけを同じ計測へ追記します。

### クエスト名の一括収集（調査用）

`tools/quest_catalog/local_text.py`でローカルのNIFLテキストを読み、`py -3 -m tools.quest_catalog.export_names`で別ファイル`QuestNames.csv`へ日本語名を出力できます。ファイル名中の番号は名前ID候補で、計測用クエストIDとは別です。既存の`Quest.csv`・`quests.csv`を更新せず、同名の出力があれば上書きしません。ゲーム由来の抽出データ・依存ソース・調査結果はGit管理対象外です。

一覧応答の追加採取は`tools/quest_catalog/build_capture.ps1`で専用DLL・ローダー・マニフェストを`tools/quest_catalog/bin/`に作ります。通常版のビルド成果物とマニフェストは維持します。配置には`tools/native_capture/autostart.ps1 -Action Install -BuildManifest tools/quest_catalog/bin/autostart-build.json`を使います。通常のゲーム操作で受信した`0B:18/1A`の本文と`1B/1C`の終端通知のみ、runの`identity-context/quest-catalog.opcat`へ最大256KiB/通知で保存します。調査用にコンパイルした版だけで有効になり、従来のOPMETA/OPCAP形式は変えません。GUIの記録開始前も動作するため、一覧取得に戦闘・クエスト受注・GUI記録操作は不要です。

`py -3 -m tools.quest_catalog.packets <quest-catalog.opcat> --output <新しいCSV>`で一覧内のIDとローカルの名前候補を結び付けます。未知の名前IDや競合は未確定のまま残し、アプリ用辞書へ自動登録しません。2026-10-20の実機一覧で19カテゴリ・810件の日本語名が一致し、既知6クエストの計測IDとの対応も確認しました。別ファイル`QuestCatalog.csv`には全810件を保持し、一覧上ID0の1件は計測との対応未確認として区別します。ライディング・トリガー・チャレンジは今回未確認で、全クエスト網羅を示すものではありません。終了時は専用マニフェストを指定して`-Action Shutdown`、ゲームを通常終了後に`-Action Remove`で追加ローダーを撤去します。

## 保存データの再生

```powershell
py -3 -m tools.combat_core ./my-recording/capture.opcap --output ./report.json --events ./events.jsonl
py -3 -m tools.combat_core.quest_replay ./my-recording/capture.opcap --output ./quest-report.json
```

出力先は新規ファイルを指定してください。元のOPCAP/OPMETAは変更しません。詳しい[取得部のビルド・配置](tools/native_capture/README.md)と[開発状況・残る確認](docs/DEVELOPMENT.md)も参照できます。

## 記録と通信

取得・集計・GUIはローカルファイルを使います。LazyParseによるテレメトリーや外部送信はありません。開発用の依存取得は明示的なビルド操作時だけ行います。

ゲーム内の人物名・ID等は記録ファイルに含まれます。画面の匿名表示は元ログ・JSONの匿名化ではありません。TXT出力の人物名には匿名表示設定を反映しますが、識別IDは残ります。`config/`と`logs/`はGit管理対象外です。この公開ソースには実機ログ・スクリーンショット・個人設定・ローカル引き継ぎ文書を含めていません。

LazyParse自身はゲームサーバーへ接続せず、ゲーム内の受信処理でデータを複写します。ゲームやWellbia自身の通信は別です。追加ローダーは任意DLLの読み込み口を利用するもので、Wellbiaを停止・無効化する処理はありません。ロード分岐への影響やアンチチート側の許容は保証していません。

## 検証範囲

2026-10-21メンテナンス後のbridge・Classicに合わせ、取得部の版チェックと登録先アドレスを更新しています。命令・パケット定義の静的照合、模擬試験、新版DLLの実起動・識別受信を確認しました。記録開始時に設置済みのフックへ不要なスレッド停止を再実行する問題を修正し、関連137試験に合格しています。**修正版での実機記録開始・ダメージ照合は未確認**です。旧版の保存ログも引き続き読み込めます。以下の実機結果はメンテナンス前の版での確認です。

特定版のJP Classicとソロの森林探索で、クリア・破棄・再受注を確認しています。「最終決戦：時空の狭間」は戦闘不能中の時計継続・帰還時停止・リトライ、「領域調査：異世界の残滓」は修正版の帰還時停止・再受注時の新規計測を実機確認しました。

「独極訓練：狂想と幻創」「独極訓練：異界と超界」はステージ間の継続と、全体クリア・失敗後の自動帰還、「決闘」（ストーリー・ハードコア固定）は失敗・再選択・クリア後の通知を採取しました。残滓・最終決戦・ディバイド最終ステージの成功通知も含め、確認済みのクリア通知形式をIDに依存しない判定へ変更しました。関連120試験で通知形式の一致・不一致、途中ステージの継続、帰還時の二重停止防止を検証済みです。この変更後の新たなゲーム起動試験は未実施です。終了後の値も別枠に保持します。履歴は同じ試行の新しい判定ルールによる保存を優先します。

帰還・失敗の規則は確認済みクライアント版とIDに限定しています。「憎悪に歪む原初の闇」や他種クエスト・パーティーの検証は残ります。JAには対象外・未判定の区別があり、ペットはJAの対象外です。実機データを使う一部の回帰試験は、非公開のfixtureがない環境ではskipします。
